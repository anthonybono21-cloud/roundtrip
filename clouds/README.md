# ET45 live cloud layer

Today's real clouds, draped over the globe. A thin shell just above the
surface, lit by the same sun as the earth below it: white in daylight, gold
along the terminator, dark over the night side, and thicker at the limb where
the line of sight runs the long way through the deck.

Built to drop into the earth dive prototype without touching any of its files.

![the globe with clouds](screenshots/hero-terminator.png)

## Integrating it

One `<script>` and one line, anywhere after the earth exists:

```html
<script src="./clouds/et45-clouds-inline.js"></script>
```

```js
ET45Clouds.attach({ THREE, renderer, scene: space, sunDir, camAlt });
```

That is all of it. The layer adds its own mesh, fetches its own imagery,
updates its own uniforms from `mesh.onBeforeRender`, refreshes itself when the
source publishes a new map, and never throws into the caller.

`sunDir` and `camAlt` are taken **by reference**, so the prototype's existing
sun vector and altitude keep driving the layer with no glue and no changes to
the render loop. Passing `renderer` is optional and only buys anisotropy and an
up-front texture upload, so a new map never costs a hitch mid-flight.

For the single-file build, `et45-clouds-inline.js` already has its fallback
texture baked in as a data URI, so `build.py` needs no new asset handling —
just include the file.

## The source

| source | fresh | resolution | CORS | licence |
| --- | --- | --- | --- | --- |
| **clouds.matteason.co.uk** ✅ | **every 3 h** | up to 8192×4096 | **yes** | CC0, EUMETSAT attribution |
| NASA GIBS (VIIRS true colour) | daily | 250 m tiled | yes | public domain |
| NASA Worldview snapshots | daily | tiled | yes | public domain |
| EUMETSAT Data Store | 15 min | full disc | n/a | **needs an account** |
| NOAA / NESDIS GOES | 10 min | full disc | unclear | public domain |

**Picked: clouds.matteason.co.uk.** It is the only free, keyless source that
publishes the thing actually needed here — a whole-earth equirectangular cloud
map *with an alpha channel*, in the exact projection a sphere's default UVs
want, refreshed eight times a day. Everything else needs work before it can be
draped on a globe.

The others fail on something specific rather than on quality:

- **GIBS and Worldview** are the authoritative NASA source and are genuinely
  excellent, but they serve *true colour* — land and cloud together, no alpha.
  Clouds have to be carved out per-pixel, and bright desert and ice read as
  cloud however carefully you do it. They are also daily rather than 3-hourly,
  built from one satellite's daytime passes.
- **EUMETSAT's own Data Store** is fresher than anything else at 15 minutes,
  but it needs a registered account and an API key, which the project rules
  rule out.
- **NOAA/NESDIS GOES** imagery is a geostationary *disc*, not a global map, so
  it covers the Americas and not Asia. Stitching a global mosaic from several
  geostationary satellites is exactly the work matteason's project already
  does, and publishes under CC0.

So GIBS is still in here as the backup, behind a per-pixel cloud extraction —
just not as the first choice.

### Attribution

Required by EUMETSAT's licence and rendered bottom-right by the demo. The
prototype already carries an attribution line; add this to it:

> Contains modified EUMETSAT data

`layer.credit()` returns the right line for whatever is actually on screen,
including a plainly different one for the offline texture, so the app never
claims live satellite data for a map that was generated.

## When the network is not there

Four sources, each falling through to the next, so the globe is never bald:

1. **Live** — the map for the current 3-hour slot.
2. **Cache** — the last live map this browser saw, kept in IndexedDB. A desk
   app gets restarted constantly; this means a restart with the network down
   still shows real clouds from earlier, and a normal restart within the same
   3-hour slot costs no download at all.
3. **GIBS** — NASA daily true colour, clouds extracted on the CPU.
4. **Bundled** — `assets/clouds-fallback.png`, generated by `make-fallback.py`.

The bundled texture is **not real weather**, and the credit line says so. It is
3D noise sampled on the sphere itself — so no date-line seam and no polar
pinching — shaped by the real zonal pattern: wet on the equator, dry in the
subtropics, wet again in the mid-latitude storm track, with the bands broken up
longitudinally so the planet reads as Earth rather than Jupiter.

The bundled texture loads from disk in milliseconds while the live map is still
in flight, so the globe is clouded from the first frame and never pops from
bare to clouded. Every later arrival crossfades over ~1.4 s rather than cutting.

## The altitude fade

The map is ~19 km per pixel, which is finer than the globe is ever asked to
show from orbit and far too coarse from close up. The layer is therefore at
full strength above **300 km** and gone by **76 km** — the same window in which
the prototype's `DETAIL_LEVELS[0]` fades its sharp satellite mosaic in. The
clouds leave exactly as the sharp ground arrives, so the descent never flies
through a blurry grey sheet.

If those altitudes are retuned in the prototype, change `fadeHighAlt` and
`fadeLowAlt` to match.

## Configuration

Everything is an option to `attach()`, and most are live-settable with
`layer.set('name', value)`.

| option | default | what it does |
| --- | --- | --- |
| `size` | `2048x1024` | source resolution; `4096x2048` costs 4× for no visible gain |
| `radius` | `1.0015` | ~9.5 km up, where cloud tops actually are |
| `opacity` | `1.0` | master fade, for dialling the whole deck back |
| `density` | `0.94` | opacity ceiling; even overcast lets a little through |
| `softLow` / `softHigh` | `0.05` / `0.92` | coverage that counts as clear sky / solid deck |
| `limb` | `1.55` | how much thicker the deck reads edge-on |
| `shade` | `0.55` | self-shading across the cloud tops |
| `nightAlpha` | `0.82` | how much the deck dims the city lights below it |
| `driftDegPerHour` | `1.2` | gentle eastward advection between refreshes |
| `fadeLowAlt` / `fadeHighAlt` | `0.012` / `0.047` | the handover window, in earth radii |
| `refreshMinutes` | `20` | how often to look for a new 3-hour slot |
| `gibs` | `true` | use NASA GIBS if the primary source is unreachable |
| `cache` | `true` | remember the last good map in IndexedDB |

`layer.status()` reports which source is showing, `layer.refresh()` forces a
re-fetch, `layer.dispose()` removes it cleanly.

## What was tested

Headless Chromium, `node test.mjs` against `node test-file.mjs`. All green:

- the live path installs and runs clean, with no console errors
- the layer visibly changes the frame (measured on/off, not assumed)
- it is at full strength from orbit, half-faded at 166 km, exactly zero by 64 km
- with no network at all it falls back and throws nothing
- a cached map survives a restart when the source is unreachable
- the built single file renders correctly opened over `file://`

**The screenshots show the bundled texture, not live weather.** This session's
network cannot reach `clouds.matteason.co.uk` — outbound access is limited to an
allowlist — so the live path was tested against a byte-identical local stand-in
served in the same format (equirectangular RGBA, alpha as coverage) and the
host was confirmed serving HTTP 200 today. The one thing not verifiable from
here is the real host's CORS header; the project documents it as enabled, and
if it ever is not, the layer falls through to the cache and then the bundled
texture rather than failing.

## Known limits

- The source mirrors the top and bottom of the map to cover the poles, which
  the satellites do not see. Barely visible on a globe, and mostly ice anyway.
- When a satellite misses a region the map has squarish holes in it. Rare, and
  it self-corrects at the next 3-hour refresh.
- Clouds do not cast shadows on the ground. That needs the earth's own shader
  to sample the cloud map, which would mean editing the prototype's files.
  It is about four lines there if it is ever wanted.
